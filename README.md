# Data Factory

DATA FACTORY — визуальная среда программирования в браузере. Создавайте проекты, собирайте программы из нод и соединений, запускайте граф и исследуйте данные выполнения. Основная модель: **Project → Graph → Nodes → Ports → Connections → Runtime**. Обучение доступно как Tutorial Campaign внутри редактора.

Стек: TypeScript strict, Phaser 4, Vite, Vitest, HTML/CSS. React и сервер не требуются. Логика симуляции не зависит от Phaser и DOM.

## Запуск

Нужен Node.js 22.12+ или 24 LTS и npm.

```bash
npm install
npm run dev
```

Откройте адрес из терминала (по умолчанию `http://127.0.0.1:5173`).

```bash
npm run typecheck
npm test
npm run build
npm run preview
```

`npm test` запускает тесты ядра, проектов, Tutorial, сохранений и генерации кода. Если доступен Python 3, дополнительно выполняется настоящий сгенерированный Python для всех учебных графов. Эти дополнительные тесты пропускаются без Python; сама среда его не использует. Путь к интерпретатору можно задать через `PYTHON`.

## Работа в редакторе

1. При первом открытии доступен Blank Factory. **New Project** создаёт новый пустой проект; **Open Project** открывает сохранённый проект или файл `.df` / старый JSON графа. **Examples** открывает изменяемую копию примера.
2. Перетащите ноду из Node Palette на Graph Canvas. Нажатие на карточку тоже добавляет ноду. Все 27 типов доступны в обычном проекте.
3. Потяните от выходного порта справа к входному слева. Можно нажать порты по очереди.
4. Выберите ноду и настройте параметры в Inspector. Constant принимает JSON: `2`, `"A"`, `true`, `[1,2]`.
5. Задайте **Input JSON** внизу и нажмите **RUN**. Повторное нажатие ставит выполнение на паузу. Обычный проект исполняет только ваш граф с вашим входом.
6. **Step** выполняет одно событие, **Stop** возвращает к редактированию. Console показывает журнал и результат, Variables — значения нод, Execution — последние 300 событий, Errors — ошибки, Profiler — счётчики текущего запуска. Code View генерирует Python / JavaScript.
7. Проекты и входные данные автоматически сохраняются в этом браузере. **Export** создаёт переносимый файл `.df` с названием, входом и графом; **Import** заменяет текущий граф из старого JSON с поддержкой Undo.

**Tutorial** открывает учебную кампанию в том же редакторе. Только в ней появляются инструкции, ограниченный набор нод, вкладка Tests и проверки примеров. Учебные графы и прогресс сохраняются отдельно от самостоятельных проектов.

Скорости: 0.25×, 0.5×, 1×, 2×, 4× и Instant. Instant пропускает анимацию при непрерывном запуске; Step остаётся наглядным даже с выбранным Instant.

| Управление | Действие |
| --- | --- |
| Мышь за корпус машины | Перемещение с привязкой к сетке |
| Правая/средняя кнопка или пробел + мышь | Панорама |
| Колесо / кнопки − и + | Масштаб |
| F | Вписать фабрику |
| Delete / Backspace | Удалить выбранную машину или связь |
| Ctrl+Z / Ctrl+Shift+Z | Undo / Redo |
| R / точка | RUN–Pause / Step |
| Esc | Отменить соединение / снять выделение |
| Ctrl+S | Сохранить локально |
| Export / Import над графом | Экспорт проекта `.df` / импорт JSON графа |

Приоритетные размеры: 1920×1080 и 1366×768. Интерфейс также проверяется при 1100×700; мобильная компоновка не входит в MVP.

## Содержимое

Примеры самостоятельных проектов: Signal Flow и Multiply Stream. Tutorial Campaign содержит десять этапов: передача значения, удвоение, +10, сравнение с 10, чётность, Split/Join, разворот строки, Branch, фильтрация массива, палиндром.

27 типов нод: Source, Output, Constant, Arithmetic, Comparator, Split, Join, Stack, Queue, Branch, Filter, Memory, Negate, Abs, Not, Length, Concat, Sum, Sort, Unique, Random, Randint, Randrange, Uniform, Choice, Shuffle, Sample. Multiply — операция `*` у Arithmetic.

Random-ноды соответствуют основным операциям [Python random](https://docs.python.org/3/library/random.html): RANDOM выдаёт число в `[0, 1)`, RANDINT включает обе целочисленные границы, RANDRANGE исключает Stop и поддерживает отрицательный шаг, UNIFORM принимает границы в любом порядке. Эти четыре ноды выдают один результат на пакет Trigger; подключённый пустой поток не даёт результатов. Без Trigger они генерируют одно значение за запуск. В текущем runtime для простого графа подключайте Source к Trigger.

CHOICE выбирает элемент массива или Unicode-символ строки; пустая последовательность вызывает ошибку. SHUFFLE выдаёт перемешанную копию массива. SAMPLE выбирает K позиций без возвращения и выдаёт массив; повторяющиеся значения исходного массива могут сохраниться. Параметры настраиваются в Inspector. Пример **Dice Rolls** демонстрирует пять бросков кубика: Source → Split → Randint → Join → Output.

Случайность вычисляется только при выполнении ноды, а просмотр Inspector её не меняет. Новый запуск генерирует новые значения; seed пока не настраивается. В браузере используется `Math.random`, Python Code View вызывает настоящий модуль `random`, поэтому конкретные результаты запусков могут различаться. JavaScript Code View по-прежнему поддерживает только исходные скалярные ноды.

Sum, Sort и Unique обрабатывают каждый массив как отдельный пакет. Sum суммирует числа (пустой массив → 0), Sort сортирует числа по возрастанию или убыванию, Unique сохраняет первые вхождения значений. Length считает элементы массива или Unicode-символы строки. Concat соединяет строки из двух входов с поддержкой broadcast. Пример **Array Summary** демонстрирует цепочку Source → Unique → Sort → Sum → Output.

Все задания доступны на карте. Для прохождения нужны все тесты; медали Compactness, Efficiency и Throughput необязательны.

## Браузерные тесты

```bash
npx playwright install chromium
npm run test:e2e
```

После сборки `npm run test:build` отдельно проверяет `dist/` через HTTP в подпапке `/algofactory/`: загрузку Phaser, редактор, сохранение после reload и отсутствие внешних ресурсов. Используется тот же `PLAYWRIGHT_CHANNEL`.

Можно использовать установленный Edge вместо загрузки Chromium (PowerShell):

```powershell
$env:PLAYWRIGHT_CHANNEL = 'msedge'
npm run test:e2e
```

Тесты сами запускают Vite или используют существующий сервер на порту 5173. Они проверяют проекты, перенос `.df`, восстановление входных данных, runtime-панели, drag/drop, соединения, перемещение, undo/redo, Step/Pause, Inspector, параметры, пакеты, удаление связей, камеру, Code View и все десять этапов Tutorial. Скриншоты и трассы ошибок — в `test-results/`.

## Статическая публикация

Публикация через ваш авторизованный GitHub CLI (`gh`) и PowerShell 7:

```powershell
# Один раз: создать публичный репозиторий, настроить Pages и опубликовать.
pwsh -File ./scripts/publish-pages.ps1 -Owner Anen135 -Repository algofactory -CreateRepository

# Повторная публикация после commit изменений:
pwsh -File ./scripts/publish-pages.ps1 -Owner Anen135 -Repository algofactory
```

Скрипт требует чистое рабочее дерево, запускает typecheck/tests/build, отправляет текущую ветку в origin, включает Pages с GitHub Actions, запускает нужный workflow, ждёт его завершения и проверяет HTTP-ответ сайта. Токен берётся из `gh auth login`, не сохраняется в проекте. Существующий чужой origin не заменяется, force-push не используется. `-NoWait` запускает публикацию без ожидания, `-SkipChecks` пропускает локальные проверки (workflow всё равно запускает тесты и сборку). Без `-Owner` используется текущий пользователь `gh`.

`npm run build` создаёт `dist/`. Загрузите содержимое этой папки на любой статический хостинг. Не открывайте `index.html` через `file://`: используйте HTTP-сервер.

Для ручной настройки без скрипта включите **Settings → Pages → Source: GitHub Actions**, затем запустите workflow **Deploy Data Factory**. Он собирает и публикует `dist/`. `base: './'` позволяет размещать игру в подпапке репозитория; маршрутизатор и настройка fallback не нужны. Автоматический запуск происходит только при изменении самого файла workflow (это также регистрирует Actions в новом репозитории); обычные изменения публикуются через скрипт или ручной запуск.

Сохранения привязаны к origin браузера. Для переноса между локальным адресом и опубликованной средой экспортируйте проект `.df`. Скрытые тесты Tutorial не показываются в UI, но входят в статический JS bundle.

```text

```

## Границы MVP

Потоки конечны; нода обрабатывает буфер после закрытия всех подключённых входов. Графовые циклы отклоняются. Текущая валидация требует Source, Output и путь между ними. Memory выполняет запись/чтение в пределах одного запуска и сбрасывается перед следующим. Произвольные for/while, функции, рекурсия и вложенные границы потоков требуют следующего этапа control flow.

Python Code View поддерживает текущие машины. JavaScript экспортирует скалярные фабрики Source/Constant/Math/Compare/Output; для потоков UI предлагает Python. Code View показывает вычисление, а не воспроизводит анимацию или тики.
