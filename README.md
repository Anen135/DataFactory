# Data Factory

> Визуальная среда программирования в браузере: соберите «фабрику» из нод-машин и соединений, запустите граф и увидите, как данные текут по проводам.

**Data Factory** — интерактивный конструктор алгоритмов. Вместо строк кода вы соединяете на графе машины: SOURCE подаёт входное значение, MATH умножает, COMPARE сравнивает, BRANCH направляет по условию, JOIN собирает поток обратно. Значения перемещаются между машинами пакетами, и весь конвейер видно в движении — как в Node-RED, Scratch или Unreal Engine.

Никакой регистрации, сервера и установки: всё работает в браузере и сохраняется локально. Модель продукта — **Project → Graph → Nodes (Machines) → Ports → Connections → Runtime**.

Встроенный курс **Tutorial Campaign** из 20 уровней проведёт от первого сигнала до массивов, строк и случайности — с пошаговыми подсказками, автоматическими тестами и медалями. **Code View** покажет тот же алгоритм текстом на Python или JavaScript.

## Возможности

- **Визуальный редактор графов** — перетаскивание машин, привязка к сетке, zoom/pan, соединение портов мышью или кликом.
- **Наглядная симуляция** — RUN / Pause / Step, скорости 0.25×–4× и Instant; по проводам летят пакеты с подписью значения.
- **27 машин** — ввод/вывод, константы, арифметика и сравнения, логика, условия, строки и массивы, коллекции, переменная и генераторы случайных чисел.
- **Отладка** — Console, Variables, журнал Execution, Errors, Profiler и Inspector выбранной машины (входы, выходы, состояние).
- **Undo/Redo** на 100 шагов и **автосохранение** в браузере.
- **Экспорт / импорт** — переносимый файл проекта `.df`, а также старые JSON-графы.
- **Code View** — генерация Python (все машины) и JavaScript (скалярные фабрики).
- **Без бэкенда** — статический сайт на TypeScript (strict) + Phaser 4 + Vite; React не нужен, логика симуляции не зависит от Phaser и DOM.

## Быстрый старт

Нужен Node.js 22.12+ (или 24 LTS) и npm.

```bash
npm install
npm run dev
```

Откройте адрес из терминала (по умолчанию `http://127.0.0.1:5173`).

| Команда | Назначение |
| --- | --- |
| `npm run typecheck` | строгая проверка типов |
| `npm test` | юнит-тесты ядра, проектов, Tutorial, сохранений и генерации кода |
| `npm run build` | production-сборка в `dist/` |
| `npm run preview` | локальный предпросмотр собранной версии |

## Первая сессия за 5 минут

1. При первом открытии доступен **Blank Factory**. **New Project** создаёт пустой проект, **Open Project** открывает сохранённый проект или файл `.df` / старый JSON-граф, **Examples** — изменяемую копию готового примера.
2. Перетащите машину из **Node Palette** на поле (или кликните по карточке). В обычном проекте доступны все 27 типов.
3. Потяните от правого (выходного) порта к левому (входному) — или просто нажмите порты по очереди.
4. Выберите машину — её параметры появятся в **Inspector**. Например, Constant принимает JSON: `2`, `"A"`, `true`, `[1, 2]`.
5. Задайте **Input JSON** внизу и нажмите **RUN**. Повторное нажатие ставит выполнение на паузу.
6. **Step** выполняет одно событие, **Stop** возвращает к редактированию. Результат — в Console, значения машин — в Variables, последние 300 событий — в Execution, ошибки — в Errors, счётчики запуска — в Profiler.
7. Проекты и входные данные сохраняются автоматически. **Export** создаёт файл `.df` (название, вход и граф), **Import** заменяет текущий граф из JSON с поддержкой Undo.

**Tutorial** открывает учебную кампанию в том же редакторе: инструкции, ограниченный набор машин, вкладка Tests и проверки решений. Учебные графы и прогресс хранятся отдельно от самостоятельных проектов.

## Управление

| Управление | Действие |
| --- | --- |
| Мышь за корпусом машины | Перемещение с привязкой к сетке |
| Правая / средняя кнопка или `Пробел` + мышь | Панорама |
| Колесо мыши / кнопки `−` `+` | Масштаб |
| `F` | Вписать фабрику в окно |
| `Delete` / `Backspace` | Удалить выбранную машину или связь |
| `Ctrl+Z` / `Ctrl+Shift+Z` | Undo / Redo |
| `R` / `.` | RUN–Pause / Step |
| `Esc` | Отменить соединение / снять выделение |
| `Ctrl+S` | Сохранить локально |

Рекомендуемые размеры окна — 1920×1080 и 1366×768; интерфейс также проверяется при 1100×700 (мобильная компоновка не входит в MVP).

## Примеры проектов

| Пример | Что показывает |
| --- | --- |
| **Signal Flow** | Простейшая фабрика: Source → Output |
| **Multiply Stream** | Умножение входного числа на константу |
| **Filter Array** | Фильтрация массива по порогу: `[2, 15, 5, 30, 10, 42] → [15, 30, 42]` |
| **Array Summary** | Unique → Sort → Sum: `[3, 1, 3, 10, -2] → 12` |

Примеры открываются как изменяемые копии: их можно дорабатывать и запускать со своими входными данными.

## Машины

**Ввод, вывод и константы**

| Машина | Назначение |
| --- | --- |
| SOURCE | Вход программы: отправляет заданное значение |
| OUTPUT | Финальный результат; принимает активную ветку |
| CONSTANT | Постоянное значение; необязательный trigger выпускает значение на каждый пакет |

**Числа и логика**

| Машина | Назначение |
| --- | --- |
| MATH | Арифметика A и B: `+ − × / %`; одна константа применяется ко всему потоку |
| COMPARE | Сравнение A и B: `== != > < >= <=` → boolean |
| ABS | Модуль числа: −5 → 5 |
| NEGATE | Смена знака каждого числа |
| NOT | Логическое отрицание |

**Потоки, условия и переменные**

| Машина | Назначение |
| --- | --- |
| SPLIT | Разбивает строку (по Unicode code points) или массив на поток элементов |
| JOIN | Ждёт завершения потока и собирает строку или массив |
| STACK | LIFO — разворачивает поток |
| QUEUE | FIFO — сохраняет порядок |
| BRANCH | Направляет data в true/false по condition |
| FILTER | Пропускает элементы data с condition = true |
| MEMORY | Переменная: write обновляет, read выдаёт текущее значение; сбрасывается при новом запуске |

**Коллекции и строки**

| Машина | Назначение |
| --- | --- |
| LENGTH | Число элементов массива или Unicode-символов строки |
| CONCAT | Соединение строк из двух входов (с broadcast) |
| SUM | Сумма чисел массива (пустой массив → 0) |
| SORT | Сортировка чисел по возрастанию или убыванию |
| UNIQUE | Удаление повторов с сохранением порядка; сравнение по содержимому |

**Случайность**

| Машина | Назначение |
| --- | --- |
| RANDOM | Число из `[0, 1)` |
| RANDINT | Случайное целое от min до max включительно |
| RANDRANGE | Случайный элемент диапазона `start..stop` (stop не входит), поддерживается шаг |
| UNIFORM | Случайное дробное число между a и b; границы можно менять местами |
| CHOICE | Элемент массива или Unicode-символ строки |
| SHUFFLE | Перемешанная копия массива (исходный не меняется) |
| SAMPLE | k позиций без возврата; результат — массив |

Случайные машины соответствуют основным операциям стандартного модуля [Python `random`](https://docs.python.org/3/library/random.html). RANDOM / RANDINT / RANDRANGE / UNIFORM выдают один результат на пакет Trigger (без Trigger — одно значение за запуск); CHOICE с пустой последовательностью вызывает ошибку. Значения считаются только при выполнении машины — просмотр Inspector их не «съедает». Новый запуск даёт новые значения; seed пока не настраивается. В браузере используется `Math.random`, а Python Code View вызывает настоящий `random`, поэтому конкретные результаты запусков могут различаться.

## Code View

По графу строится промежуточное представление (IR), которое генераторы превращают в текст:

- **Python** — поддерживает все текущие машины; потоки представлены списками, пары и broadcast — явными операциями.
- **JavaScript** — экспортирует скалярные фабрики: Source / Constant / Math / Compare / Output.

Code View показывает вычисление, а не воспроизводит анимацию или тики. Для потоков UI предлагает Python.

## Формат проекта

Проект — переносимый документ `.df` (JSON): название, входные данные и граф. Runtime и история команд в него не входят, поэтому файл легко открыть на другом компьютере или в опубликованной версии (**Export → Open Project**), а старые JSON-графы тоже открываются как самостоятельные проекты. Сохранения в браузере привязаны к его origin — для переноса между локальным адресом и опубликованным сайтом используйте `.df`.

## Разработка

### Проверки

```bash
npm run typecheck   # строгий TypeScript
npm test            # юнит-тесты (Vitest)
```

`npm test` покрывает ядро, проекты, Tutorial, сохранения и генерацию кода. Если доступен Python 3, дополнительно выполняется настоящий сгенерированный Python для всех учебных графов; без Python эта группа пропускается (путь к интерпретатору задаётся через переменную `PYTHON`).

### Браузерные тесты (e2e)

```bash
npx playwright install chromium
npm run test:e2e
```

Тесты сами поднимают Vite (или используют существующий сервер на 5173) и проверяют редактор end-to-end: проекты, перенос `.df`, drag-and-drop, соединения, движение машин, undo/redo, Step/Pause, Inspector, удаление связей, камеру, Code View и все двадцать уровней Tutorial. `PLAYWRIGHT_CHANNEL=msedge` заменит загрузку Chromium на установленный Edge. После сборки `npm run test:build` проверяет `dist/` через HTTP в подпапке `/algofactory/`. Скриншоты и трассы ошибок — в `test-results/`.

### Структура репозитория

```text
src/core/             независимая симуляция, машины, граф и проверки
src/state/            редактор, история команд, управление запуском, сохранения
src/renderer/         Phaser-сцена: камера, порты, линии и пакеты
src/ui/               HTML-панели, tutorial, обработчики UI
src/content/levels/   учебные уровни и наборы тестов
src/code/             промежуточное представление и генераторы кода
e2e/                  браузерные проверки Playwright
docs/                 архитектура, игровой дизайн, расширение проекта
```

## Публикация

`npm run build` создаёт `dist/` — его можно загрузить на любой статический хостинг (запускайте с HTTP-сервера, а не через `file://`). В репозитории есть готовый GitHub Actions workflow **Deploy Data Factory**: он прогоняет тесты и сборку и публикует `dist/` в GitHub Pages. Настройка: **Settings → Pages → Source: GitHub Actions**, затем ручной запуск workflow. `base: './'` позволяет размещать сборку в подпапке репозитория.

Для повторяемой публикации из CLI (нужны `gh` и PowerShell 7) подходит скрипт:

```powershell
pwsh -File ./scripts/publish-pages.ps1 -Owner <логин> -Repository <репозиторий> -CreateRepository
pwsh -File ./scripts/publish-pages.ps1 -Owner <логин> -Repository <репозиторий>
```

Скрипт требует чистое рабочее дерево, прогоняет typecheck / тесты / сборку, включает Pages и ждёт завершения деплоя. Флаг `-NoWait` не ждёт завершения, `-SkipChecks` пропускает локальные проверки; без `-Owner` используется текущий пользователь `gh`. Токен берётся из `gh auth login` и в проекте не хранится.

## Что пока не поддерживается

- Циклы в графе (отклоняются валидацией), произвольные for/while, функции и рекурсия — следующий этап control flow.
- Бесконечные потоки: буферы конечны, у запуска есть лимит действий.
- JavaScript-генератор пока покрывает только скалярные фабрики.
- Мобильный интерфейс и серверная синхронизация / мультиплеер.
