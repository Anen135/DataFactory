# Как добавить машину

## 1. Определение

Добавьте объект в массив definitions в `src/core/machines.ts`. Все машины используют один контракт `MachineDefinition`. Например, отрицание чисел:

```ts
{
  type: 'negate',
  name: 'NEGATE',
  description: 'Меняет знак каждого числа.',
  icon: '−',
  color: 0x79b5f1,
  ports: [input('in', ['number']), output('out', ['number'])],
  defaults: {},
  fields: [],
  execute: context => out(context.inputs.in.map(value => -number(value))),
}
```

`input`, `output`, `out`, `number` доступны в этом файле. За его пределами создайте `Port` и `MachineResult` обычными объектами и зарегистрируйте definition через `MachineRegistry.register()`.

## 2. Контракт исполнения

`execute` получает:

- `input`: исходный DataValue теста;
- `inputs`: объект с буферами по ID входного порта;
- `connected`: множество реально подключённых входных портов;
- `config`: параметры машины;
- `memory`: состояние текущего вызова;

Верните `{ outputs: { out: [...] }, state?: {...} }`. Ключи outputs должны соответствовать выходным портам. `state` показывается в инспекторе. Не возвращайте undefined, null, NaN/Infinity, DOM/Phaser-объекты. Бросайте Error с понятным текстом при недопустимых данных.

Пустой поток — `[]`; массив как один пакет — `[[1,2]]`. Их нельзя путать. Не изменяйте входные массивы: для reverse используйте копию. Закрытие всех выходных потоков выполняет scheduler автоматически, включая пустые ветки.

Все подключённые входы завершаются до `execute`. В MVP машина вызывается один раз за тест. Для бинарной обработки используйте `pairs(a,b)`: она реализует singleton broadcast и проверяет длины. Для optional порта используйте `connected.has(id)`, чтобы различать отсутствие подключения и пустой поток.

## 3. Параметры и типы

Добавьте defaults и fields:

```ts
defaults: { factor: 2, mode: 'multiply' },
fields: [
  { key: 'factor', label: 'Множитель (JSON)', kind: 'value' },
  { key: 'mode', label: 'Режим', kind: 'select', options: ['multiply', 'divide'] },
],
```

UI создаст controls автоматически. Defaults и select options проверяются при настройке/импорте/запуске. Предметные ограничения (`factor` должен быть числом и т.д.) проверяйте в execute; при необходимости расширьте общий config validator. Если выходной тип зависит от настройки, добавьте правило в `outputTypes` в `src/core/graph.ts`. Для фиксированного типа достаточно types выходного порта.

## 4. Доступность

В обычных проектах новое определение автоматически появится в Node Palette. Для включения в Tutorial добавьте его тип в `availableMachines` нужного этапа в `src/content/levels/index.ts`. Renderer автоматически использует metadata/ports для формы, цветов и соединений. Palette использует имя и описание; при желании добавьте короткую подпись в `src/ui/panels.ts`.

## 5. Тесты

Добавьте тесты обработчика и хотя бы один граф `Source → Negate → Output` через `Simulation`. Проверьте отрицательные значения, ноль, поток из нескольких пакетов, пустой поток, неправильный тип, а также сериализацию нестандартных параметров. Новая машина не должна требовать Phaser для тестов.

Запуск:

```bash
npm run typecheck
npm test
npm run build
```

## 6. Code View

Для Python добавьте emitter по operation в `src/code/generators.ts`. Он получает IR-node и функцию получения входного выражения. Добавьте тест, который выполняет сгенерированный код, если это поддерживает окружение. До появления emitter UI честно сообщает, что экспорт этой машины не поддержан.

Если новая машина требует итераций или повторного вызова, не обходите контракт добавлением обратной связи: сначала расширьте control-flow модель Simulation/IR и execution budget.
