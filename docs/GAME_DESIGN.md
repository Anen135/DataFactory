# Игровой дизайн Data Factory

## Учебная петля

Задание → сборка фабрики → наблюдение потока → инспекция ошибки → исправление → тесты → следующий алгоритм → эквивалентный код.

Игрок сначала видит вычисление физически: число появляется у Source, проходит по линии и меняется в машине. Затем связывает работу машин с выражениями, условиями, потоками и переменными. Code View связывает эту модель с текстовым кодом.

## Уровни

| № | Задача | Понятие |
| --- | --- | --- |
| 1 | Передать число | Source, Output, связь |
| 2 | Умножить на 2 | Константа и два входа |
| 3 | Прибавить 10 | Настройка операции |
| 4 | Число > 10 | Boolean |
| 5 | Чётность | Композиция `%` и `==` |
| 6 | Разделить и собрать строку | Поток и завершение |
| 7 | Развернуть строку | LIFO |
| 8 | Выдать POSITIVE/NEGATIVE | Branch и gated Constant |
| 9 | Оставить числа > 10 | Filter и массивы |
| 10 | Палиндром | Fan-out и повторное использование входа |
| 11 | Модуль числа | ABS |
| 12 | Смена знака | NEGATE |
| 13 | Число ≤ 10 | Логическое НЕ и инверсия сравнения |
| 14 | Длина строки | LENGTH и Unicode-символы |
| 15 | Строка + суффикс | CONCAT и строковая константа |
| 16 | Сумма массива | SUM и пустой массив |
| 17 | Сортировка | SORT и порядок |
| 18 | Уникальность | UNIQUE и сравнение по содержимому |
| 19 | Среднее арифметическое | Композиция SUM / LENGTH / деление |
| 20 | Развернуть массив | Поток элементов и Stack |

Каждый уровень имеет три видимых примера и дополнительные скрытые тесты. Важные крайние случаи: ноль, отрицательные числа, пустые строки/массивы, Unicode. Ноль на уровне 8 относится к NEGATIVE; пустая строка на уровне 10 считается палиндромом.

## Правила машин

- Constant без trigger выдаёт одно значение. С подключённым trigger — по значению на входной пакет. Пустая ветка ничего не выдаёт.
- Math и Compare принимают A/B; singleton broadcast позволяет одной константой обрабатывать поток.
- Branch направляет data по соответствующему boolean. Для замены числа строковым сообщением используйте Constant с trigger.
- Filter сохраняет data, для которых condition=true; сначала создайте условия через Compare.
- Split работает по Unicode code points, а не UTF-16 units. Составные grapheme clusters не объединяются.
- Join(string) принимает только строки, Join(array) принимает все поддерживаемые значения.
- Stack/Queue собирают конечный поток, затем выдают LIFO/FIFO.
- Memory в MVP — запись всего входного буфера и чтение итогового значения; не произвольное чередование команд по времени.

## Отладка

При запуске редактирование заблокировано. Pause останавливает clock, Step выполняет одно событие. Создание и передача пакета — разные шаги. Инспектор показывает входы, выходы и состояние выбранной машины; консоль — историю последних 80 событий. Скорость меняет только воспроизведение.

Валидатор сообщает конкретную причину: «У машины MATH не подключён вход B», «Несовместимые типы», «Деление на ноль», «Обнаружен цикл». Ошибки параметров не должны повреждать сохраняемый граф.

## Прохождение и оценки

Условие прохождения — ровно один ожидаемый итоговый DataValue на каждом тесте. Это может быть и массив, упакованный в один пакет. Несколько отдельных Output-пакетов не эквивалентны одному массиву.

Количество машин и связей относится к текущему графу. Operations — число обработок машин, ticks — число логических действий. В итоговой статистике operations/ticks суммируются по всему набору тестов; текущий toolbar показывает только анимируемый пример. В MVP одна машина выполняется один раз за тест, поэтому operations отражает число batch-операций, а не количество отдельных арифметических вычислений внутри буфера.

Медали не блокируют прогресс. Compactness сравнивает число машин с порогом, Efficiency — операции, Throughput — тики. Рекорды сохраняются независимо по каждой метрике. Карта не закрывает задания за жёсткой цепочкой: можно экспериментировать с любым уровнем.

## Tutorial

Уровень задаёт массив шагов с текстом и условием (`machine`, `connection`, `completed`). UI ищет первый невыполненный шаг по состоянию графа. Никакой привязки к конкретному ID Source или координате нет. Система повторно применима к другим уровням с теми же видами событий.

## Визуальная система

Тёмное поле, спокойная точечная сетка и разноцветные акценты по категории. Источник — зелёный, приёмник — янтарный, арифметика — голубая, потоки — бирюзовые, память — сиреневая. Различение также обеспечивают имя и символ, а не только цвет. Пакеты имеют яркую точку и подпись значения. Основные панели выполнены HTML/CSS, поле — Phaser Graphics/Text.

## Границы

Нет сложных ассетов, серверной авторизации, multiplayer, мобильного редактора, бесконечных потоков, пользовательского JS execution, for/while и рекурсии. Скрытые тесты скрыты только интерфейсом и доступны в статическом bundle.

Code View — учебный экспорт, не универсальный компилятор. Python охватывает все машины и подтверждён тестами для всей кампании; JavaScript пока поддерживает скалярные фабрики. IR сохраняет детерминированный порядок объединения веток. Экспорт предполагает допустимые входные типы и не включает visual debugger, тайминг, тики или импорт кода обратно.
